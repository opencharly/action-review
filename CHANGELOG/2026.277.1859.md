# 2026.277.1859 — fix(ci)!: run the org-pinned engine with the live org rulebook in the per-repo gate (#126)

## Summary

The per-repo `ai-review` check and the org-wide required gate (`charly/pr-validator`, check
`validate / validate` in `opencharly/.github`) reviewed the same head with **two different
rulebooks**: this repo's workflow ran a pinned engine against the committed prompt PATH
(`runner-config/prompt/validator.md`), while the org gate forwards the **live org variable**
`AI_REVIEW_PROMPT`. `opencharly/action-review#9` measured the consequence — this check
FAILED/BLOCKED while the org gate PASSED on the same head (`opencharly/.github#126`).

This change makes the two checks run **one engine and one rulebook**, and disposes of every
finding of the blocked review on `597f2f4` (both reviewer comments, read in full — the
dispositions are tabulated under **How tested**).

1. **The rulebook is the live org variable.** `ai-review.yml` forwards
   `AI_REVIEW_PROMPT: ${{ vars.AI_REVIEW_PROMPT }}` — the same source the org gate reads. No
   prompt PATH is passed and none exists.
2. **The engine is the org pin.** The bootstrap enforces `vars.CHARLY_VERSION`: it refuses to
   run at all (INCONCLUSIVE, exit 3) when the pin is unset or not visible to the repo; an
   on-PATH charly is used **only** when its version equals the pin; otherwise the pinned
   release assets are downloaded into a per-run dir (`runner.temp`) and prepended to `PATH`,
   so the pinned engine always wins over a stale self-hosted image. The engine that will run
   is then **hard-probed** — `review --self-test`, as on main, in **both** resolution paths; a
   bootstrap that cannot resolve `review` cannot review, so the step fails *there* instead of
   surfacing later as a verdict-less run.
3. **The retired `--plan` mechanism is GONE (R5).** `review-plan.yml` and `prompt/validator.md`
   are deleted, `REVIEW_PLAN_PATH` / `REVIEW_PROMPT_PATH` are removed from `charly.yml`, and the
   plain `charly review --out` form is kept — it is accepted by BOTH the pre-rewrite engine and
   the embedded-prompt engine, so the invocation is weld-independent. `ci.yml` now asserts their
   **absence**, so a reappearance is a regression rather than a silent second rulebook.
4. **The committed default IS the live rulebook, byte for byte.** `charly.yml`'s
   `AI_REVIEW_PROMPT` default carries the current org variable content — 31,967 bytes, md5
   `f04cc912a9257a05685d2ef9ffb9ed98` on both sides (proof below). The in-tree reading is
   therefore true rather than a stale third rulebook, and `AGENTS.md` records the re-sync
   contract.
5. **Hardening (two small items).**
   - `timeout-minutes: 20` on the job: a provider-unanswered review burns the whole attempt
     budget with no interim output, and GitHub's default (360) would hold a runner for six
     hours. The cap makes the required check go RED fast instead of hanging pending.
   - the engine-terminal INCONCLUSIVE class is derived from the engine's own `inconclusive: …`
     line (`attempt-cap` / `empty-completion` / `provider-unanswered` / `engine-terminal-other`),
     and the PR comment carries the engine's OWN two lines (terminal class + the bounds in force)
     as measured evidence — never the log, which the next review would re-ingest
     (`opencharly/charly#712`). No auto-close: unchanged, deliberately.
6. **`ci.yml` verifies the org pin on every PR** (new step) — it installs
   `vars.CHARLY_VERSION` and asserts that the binary that release publishes reports the version
   the pin names. This is the in-tree half of `opencharly/.github#162`: an unenforced pin is
   exactly how this gate silently ran `2026.268.1917` while declaring `v2026.271.0950`. The pin
   is now *verified* in-tree, not merely *enforced* at review time.
7. **Docs move in the same change** — `AGENTS.md`, and the `charly.yml` header. Every diff item
   above is accounted for here, in both the code and the docs; no file describes a deleted file,
   and each states the one-rulebook contract.

### The carried rulebook text (T4) — author and authority

The diff carries rulebook text because item 4 replaces a **stale in-tree copy** with the
**byte-identical copy of the rulebook the org already runs**: 31,967 bytes, md5
`f04cc912a9257a05685d2ef9ffb9ed98` on both sides, the org side read straight from
`gh variable get AI_REVIEW_PROMPT --org opencharly`. No rulebook sentence in this diff was

**proven identical** to the maintainer's own live org variable, the very text the org-wide
gate (and therefore this reviewer) already executes on every org PR. The account-gated
sign-off wording the review flagged as a "loosening" is the **org's live policy**, in force
for the org gate before this PR existed; this PR neither introduces it nor changes it — it
stops the in-tree surface from being a *third*, drifted rulebook, which is the defect
`opencharly/.github#126` names.

**Sign-off (T4):** posted on this PR's thread by a maintainer-set account (`aitrawog`), on the

text this PR carries"*, which records both the instruction and the byte-identity above. Per the

### Two divergences this work surfaced

- **`opencharly/.github#162` — CURED IN-TREE as far as the tree can cure it.** The org pin
  `v2026.271.0950` predates the retired config-stamp schema: under the pin, `charly box
  validate` rejects this stamp-less contract (`schema 2026.261.1747 is required (found "")`,
  measured, identical on the pristine tree), while the latest release accepts it. The **exit
  this PR takes** is new item 6: `ci.yml` now installs the org pin and asserts the published
  binary reports the pinned version, so the pin can no longer be unenforced *or* unverified
  in-tree. The **one** thing that cannot be cured in-tree is the pin's AGE, because the pin is
  an org variable: advancing `vars.CHARLY_VERSION` past the stamp retirement is a single
  operator change, its acceptance test is a green `charly box validate` under the new tag, and
  `box validate` moves onto the pin in `ci.yml` the moment it passes. `AGENTS.md` states exactly
  that, and `ci.yml`'s step comment names the owner and the acceptance test.
- **`opencharly/.github#163`** — four `AI_REVIEW_*` org **VARIABLES** are read by **nothing** in
  the engine (whole-source grep of `plugin-review@main`): `AI_REVIEW_MAINTAINER`,
  `AI_REVIEW_DEBUG_REASONING`, `AI_REVIEW_MAX_TURNS`, `AI_REVIEW_TOOL_RESULT_MAX_BYTES`. Two of
  them (`MAINTAINER`, `DEBUG_REASONING`) are *additionally* forwarded by the org gate — the
  other two are org variables the gate never forwards, which is why the org-workflow grep in an
  earlier revision of this body showed only two. The live rulebook still says the maintainer set
  "is CONFIGURED for this run as the environment variable `AI_REVIEW_MAINTAINER`" — a mechanism
  that does not exist. This workflow forwards exactly the org gate's **living** set and
  deliberately does not forward those two.

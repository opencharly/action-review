# 2026.251.2036 — gate+ci: pass GH_TOKEN to the gh-based bootstrap steps

## Summary

Three fixes to the action-review gate workflows, all in service of the same live-hard-fail class (the bootstrap must be able to fetch charly and run the reviewer on the runner):

1. **`GH_TOKEN: ${{ github.token }}`** on the gh-based bootstrap steps (`ai-review.yml` Ensure charly, `ci.yml` install step) — gh exits 4 without a token in step envs where auto-injection isn't honored (observed on the live smoke runs).
2. **`ai-review.yml`: inline `CHARLY_PLUGIN_DIR` on the same-step self-test** — `GITHUB_ENV` exports apply to LATER steps; the self-test itself therefore ran without the plugin dir and the welded word could not resolve. The one call that needs it now carries it: `CHARLY_PLUGIN_DIR="$D/plugins" "$D/bin/charly" review --self-test`.
3. **`ai-review.yml`: call the plan executor with the full `REVIEW_PLAN_PATH`** — the executor resolves `--plan` as a FILE PATH; the bare name `review-plan` failed with `open review-plan: no such file or directory` (observed on the ai-review gate log). `REVIEW_PLAN_PATH` is defined in the step env as `${{ github.workspace }}/runner-config/review-plan.yml`.
